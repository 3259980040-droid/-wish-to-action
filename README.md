# 愿望到行动 · wish-to-action

帮助 Agent 把“我想做一个……”推进成可判断、可执行的下一步，并在过程中补充初学者需要的知识。

**实验版：0.2.0-experimental。** 面向 Codex 和 DeepSeek Harness（dsh）的中文 Agent Skill。它是一套协作方法，不是独立应用，也不提供模型、搜索服务或 MCP 连接。

> 用户表达的是目标，往往还不知道完整规格。Agent 应主动研究、寻找成熟资源、补足必要缺口，而不是把所有未知都变成问卷。

## 能帮什么忙

- 想做一个小项目，却不知道需要什么、该从哪里开始。
- 想解决实际问题，却不知道现成工具、开源项目是否已经够用。
- 面对陌生领域，需要理解必要阶段、术语和中间产物。
- 对视觉结果只有“高级一点”“感觉不对”的判断，需要借助参考和比较变成具体修改依据。

明确的小修改、简单问答、已经确定方案的普通执行，通常不需要启动需求扩充。

## 核心方法

1. **保持目标。** 扩充必要信息，保留自主探索；可选增强不自动变成必做事项。
2. **主动找资源。** 自行搜索工具、开源项目、组件、模板、资料或素材，说明具体来源、复用部分和剩余工作。
3. **在决策点帮助学习。** 用通俗解释让用户理解当前选择，不要求先掌握整套领域知识。
4. **把追问留给关键决定。** 事实自行查，低风险缺口采用可回退的假设；尊重当前授权。
5. **交付可判断的进展。** 已授权实施就推进工作；只要求研究就给出能帮助决定的方案。

资源复用可分为直接使用（USE）、改造（FORK）、借用（BORROW）、参考（REFERENCE）和自建（BUILD），但不要求每次填完整矩阵。实际用途优先现成方案；学习用途保留适合自己实现和解释的部分。

视觉任务采用 Reference + Comparison + User Feedback + Visual Dimension Analysis，避免只把模糊反馈扩写成更多形容词。

## 安装

可安装的完整目录是 [`skills/wish-to-action`](skills/wish-to-action)，不要只复制 `SKILL.md`，两份参考文件也需要保留。

### Codex

可以直接把下面这段发给具有 Skill Installer 的 Codex：

```text
请从 https://github.com/3259980040-droid/-wish-to-action 安装
skills/wish-to-action，作为我的用户级技能。
安装后检查是否能被发现，并告诉我如何显式选择它。
```

也可以把整个 `wish-to-action` 文件夹放入当前 Codex 支持的用户级 skills 目录。作者的本机验证使用 `$CODEX_HOME/skills`（通常为 `~/.codex/skills`）；其他版本的目录规则请以 [Codex 官方技能说明](https://learn.chatgpt.com/docs/build-skills) 和安装器为准，避免在多个目录放不同副本。

安装后在新对话中通过技能选择器选取，或使用 `$wish-to-action`。具体按钮位置取决于宿主版本。`agents/openai.yaml` 保留自动选择策略，但实际是否选择仍由宿主和模型决定。

### DeepSeek Harness（dsh）

把整个 `wish-to-action` 文件夹复制到**实际运行实例**的 `$DSH_HOME/skills/`：

```text
<DSH_HOME>/skills/wish-to-action/SKILL.md
<DSH_HOME>/skills/wish-to-action/references/resource-discovery.md
<DSH_HOME>/skills/wish-to-action/references/visual-feedback.md
```

不同桌面/开发实例的 home 可能不同。先确认运行实例使用的目录；不要仅根据用户名或一个已存在的 `.dsh` 文件夹猜测。

`agents/openai.yaml` 是 Codex 显示配置，dsh 不依赖它。如果使用 SkillHub 等选择插件，需要让本对话可见该技能，再用 `/wish-to-action` 显式调用。插件开启表示可用，不等于本轮正文一定已加载。

## 怎么用

只需表达目标和已知限制，不必写完整规格。例如：

```text
我想做一个本地图片管理工具，主要用于收集画风和视觉参考。
我会一点 Python，但不知道现成工具够不够用。
请先研究并缩小范围，不创建项目、不安装软件。
```

```text
我想做一个以后可以面试展示的小项目，但没完整做过项目。
先帮我找到一个规模合适的方向，并解释当前需要理解的知识。
```

```text
这个画面感觉不对。我有两张参考，请比较构图、色彩和视觉层级，
先指出最值得修改的一处，并说明如何判断改好没有。
```

需要更确定的选择时，在上面的请求前显式选择技能。不要把“用户必须记住名字”当作唯一入口，优先使用宿主提供的选择界面。

## 如何确认使用了

首次应用后，技能要求模型在最终回复保留：

> 本次使用：愿望到行动 · 0.2.0-experimental（已读取技能正文）。

这行是便于观察的模型说明，**不是系统级证明**。可靠证据是实际正文注入或工具读取记录。dsh 的显式调用可能由宿主直接注入正文，因此没有额外 `skill` 工具调用不一定表示没加载。

若要排查，可问：“请说明本轮实际读取的技能名称、版本和来源；没有读到就明确说没有。”核对记录后再下结论。

## 测试与限制

测试请求和评审方法见 [`evals/README.md`](evals/README.md)。当前是少量诊断样本，不能推导稳定触发率或稳定质量收益。

- 已观察到过长回答、过多追问和部分过度概括；使用标记不代表质量通过。
- 能否搜索、读取图像或执行工具，取决于宿主实际能力和权限。
- 自动选择存在不确定性，宿主插件的可见性开关会影响技能发现。
- 文档层面适配不等于软件已安装实测；关键事实仍需当次核实。
- 核心方法两端共用，不保证不同模型产出完全相同。

反馈时提供脱敏请求、模型/宿主、是否显式选择、实际加载证据，以及具体哪里帮上忙或增加了负担。不要上传凭据、私人图片或完整个人会话日志。
