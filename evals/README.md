# 行为验证

不要用“模型说用了技能”代替加载证据，也不要用字数或搜索次数判定质量。案例均为虚构，不构成用户画像。

## 重现方法

1. 使用干净会话，记录宿主、模型、版本、工具权限和技能正文哈希。
2. 0.3 专项请求见 `cases-v0.3.json`；`cases.json` 保留旧版诊断请求。自动选择测试不写技能名；显式测试通过宿主选择同一技能。
3. 保存正文注入/读取记录、可见答复、调用类型和完成状态，不公开凭据或原始个人会话。
4. 若模型提问，记录答案；对照组使用相同答案，避免把不同时间预算、兴趣等条件误判成技能作用。
5. 先看成果和边界，再检查行为证据；单次成功只代表该次样本。

## 评审维度

| 维度 | 看什么 |
|---|---|
| 加载 | 元数据可见、实际正文读取、使用说明是否一致 |
| 资源 | 是否主动找到具体可用来源，说明复用位置与缺口 |
| 范围 | 是否保持一个当前可完成的目标，没有扩成完整路线 |
| 教学 | 是否解释眼下有用的概念，不把知识地图变成必修清单 |
| 决策 | 是否自行处理可查事实和可回退缺口，避免重复追问 |
| 证据 | 是否区分检索结果、推断和实测，核实关键推荐功能 |
| 不误触发 | 简单修改和已定方案能否直接完成 |

## 已有诊断样本

0.2 开发期间使用 dsh SDK、`deepseek-official / deepseek-flash` 做了五轮内容测试：旧版资源案例、新版两轮资源案例、新版两轮学习案例。新版四轮均实际读取资源参考；旧版本身也会搜索成熟工具，因此不能把搜索能力全部归功于新增参考。

最后学习案例能给出一个小型本地记录汇总方向，复用标准库并保留自己实现的逻辑；资源案例仍有偏长和追问偏多的问题。所有内容案例均只研究，未出现安装、shell 探测或创建项目的调用。

2026-10-08 收尾回归：

| 宿主 / 模型 | 案例 | 观察结果 |
|---|---|---|
| dsh SDK / deepseek-flash | 不写技能名的模糊资源需求 | 主动调用 `skill`，实际读取 0.2 正文与资源参考，完成资源研究 |
| dsh SDK / deepseek-flash | 简单错字修正 | 直接返回修正句，零工具调用 |
| Codex CLI / gpt-6.1-sol | 不写技能名的模糊资源需求 | 尝试读取用户级技能，但只读测试环境拒绝该命令；如实说明未加载，不能计为正文加载通过 |
| Codex app-server / gpt-6.1-sol | 原生 `skill` 类型显式输入 | 宿主接受已安装技能路径，正常返回小练习方案和正确版本使用说明；无需模型执行 shell 读取 |
| Codex CLI / gpt-6.1-sol | 简单错字修正 | 直接返回修正句，无需求扩充 |
| Codex CLI / gpt-6.1-sol | 已定方案的 CSV 代码请求 | 只返回代码，无重新选型和搜索；合成 CSV 用例检查通过 |

Codex 的 CLI 测试使用只读环境；网络 WebSocket 失败后回退到 HTTPS，最终请求完成。上述限制没有通过放宽测试权限规避。原生显式入口与 CLI 自动加载是两条不同路径，不能互相代替证明。

dsh 的自动加载样本通过，不代表所有插件组合或每轮对话都稳定触发。原生显式输入被宿主接受、来源文件读回校验和正确版本回复一起支持集成结论，但用户仍应查看实际宿主记录，不能只凭版本标记判定质量。本仓库只发布脱敏的案例和结论，不发布个人原始会话日志。

自动化采用 [Codex 官方非交互接口](https://learn.chatgpt.com/docs/non-interactive-mode)、本机 app-server 协议及 dsh SDK。更多方法参见 [OpenAI 的技能评估说明](https://developers.openai.com/blog/eval-skills)。

## 已知限制

小样本、非盲评、模型输出随机，SDK/CLI 与桌面组合也可能不同。当前结果不构成稳定成功率、成本节约比例或相对基础模型的因果收益证明。视觉判断和完整实施仍需另外测试。


## 0.3 自然对话试验

专项案例见 [cases-v0.3.json](cases-v0.3.json)，七项当前均未执行。另已完成五轮既有长对话的记录审查，见[脱敏观察记录](observations-v0.3.md)。二者不是同一组测试，不能将长对话观察计入专项案例的通过数。显式与隐式、全新会话与已有长会话分开统计。现有长会话带有旧版加载历史，不作为纯净的新会话首次发现证明。

用户先自然讨论项目，不提供技能名、仓库名单或评分标准；记录完成后再核对技能读取路径/正文版本、参考使用、相关研究、适配判断及是否过早锁定方案。不要中途催促调用，以免改变测试条件。

触发、读取、行为、实际帮助分别评价。对照模型条件及工具权限一致；模型可以选择不同合理来源，不以命中预设项目名判定成功。资源案例还包含非视觉领域，避免只对已写入索引的例子有效。
